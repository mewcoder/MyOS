# MyFav 网站布局设计稿

> 状态：静态设计稿已完成，待视觉与信息架构确认  
> 范围：首页、网站列表、GitHub 列表、文章列表、文章详情、全局搜索、移动端导航
> 设计稿：[打开静态交互原型](./prototype/index.html)

## 1. 设计方向

### Visual thesis

一座安静、温暖但高效的个人互联网书架：纸张质感的底色、墨色排版、少量陶土红强调，用编辑式列表代替卡片墙。

### Content plan

1. 首页负责回答“最近收藏了什么”，并提供三类内容入口。
2. 列表页负责搜索、分类、标签和快速扫读。
3. 文章详情负责沉浸阅读、回到原文和记录 GitHub Issues 笔记。
4. 博客暂不进入主导航；有稳定原创内容后再开放。

### Interaction thesis

- 页面切换保留当前阅读位置感：内容列表以轻微上移和渐显进入，不使用大幅滑动。
- 搜索使用一个跨页面共享的全屏层，桌面 `⌘/Ctrl + K`、移动端点搜索按钮进入。
- 列表行 hover/focus 只改变标题下划线、类型标记和右侧箭头，不抬升整张卡片。

## 2. 设计原则

- **内容先于装饰**：标题、简介、分类和来源始终比图标、统计数字更醒目。
- **卡片不是默认容器**：列表使用留白和细分隔线；只有搜索结果浮层与错误提示使用独立面板。
- **一个主强调色**：链接和当前状态使用陶土红；GitHub、X、微信只用中性色来源标记。
- **首页不是仪表盘**：不显示统计卡片、趋势图或“共收藏 N 条”的大数字墙。
- **阅读页比导航更重要**：进入文章详情后减少全局导航存在感，把宽度留给正文与图片。
- **移动端不是桌面缩小版**：分类栏变为水平滚动，搜索变为全屏，文章目录变为抽屉。

## 3. 信息架构

```text
MyFav
├── 首页                    /
├── 网站                    /sites
│   └── category / tag / q
├── GitHub                  /repos
│   └── category / tag / q
├── 文章                    /articles
│   ├── category / tag / month / q
│   └── 文章详情             /articles/:yyyy-mm/:slug
│       └── GitHub Issues 笔记（Utterances）
└── 博客（后续开放）          /blog
```

主导航只显示：首页、网站、GitHub、文章。博客在内容与发布流程成熟前不显示空入口。

## 4. 全站框架

### 4.1 Desktop（≥ 1100 px）

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ MyFav       首页   网站   GitHub   文章   [搜索收藏或问 AI…  ⌘K]  ◐  GitHub │ 64
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│                         page content · max 1240                              │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 顶栏 sticky，高 64 px，背景使用 92% 纸张色与轻微 blur。
- 内容最大宽度 1240 px，左右最小 gutter 32 px。
- Logo 左对齐，主导航紧随其后；常驻搜索框、AI 设置、主题和源码入口位于右侧。
- 顶栏只使用一条底部分隔线，不为每个按钮增加独立底色。

### 4.2 Tablet（768–1099 px）

```text
┌──────────────────────────────────────────────────────────┐
│ MyFav       网站  GitHub  文章   [搜索收藏或问 AI…]  ◐   │
├──────────────────────────────────────────────────────────┤
│                    page content                          │
└──────────────────────────────────────────────────────────┘
```

- 隐藏“首页”文字入口，点击 Logo 回首页。
- 搜索框保持在顶栏，不保留快捷键提示。
- 列表页分类 rail 改为顶部横向分类栏。

### 4.3 Mobile（≤ 767 px）

```text
┌──────────────────────────────┐
│ MyFav  [搜索收藏或问 AI…] ◐ │ 56
├──────────────────────────────┤
│                              │
│         page content         │
│                              │
├──────────────────────────────┤
│ 首页    网站   GitHub   文章 │ 60 + safe area
└──────────────────────────────┘
```

- 顶栏只保留 Logo、常驻搜索框、AI 设置和主题按钮。
- 底部导航固定，四个入口等宽，触控区域不小于 44×44 px。
- 页面内容底部增加 `80px + env(safe-area-inset-bottom)`，避免被导航遮挡。
- 文章详情隐藏底部主导航，改为顶部返回按钮，减少阅读干扰。

```

- 列表页不重复显示大标题和说明，进入页面后直接看到筛选与内容。
- 左侧 rail 宽 208 px、sticky；显示分类与数量，标签只显示常用项。
- 搜索统一放在全站顶栏，可切换关键词搜索与 AI 数据问答；列表顶部只显示当前范围和数量。
- GitHub 主列表在 desktop/tablet 使用两列紧凑网格；一条仓库记录只占半行宽度。
- 网站主列表与 GitHub 一致，在 desktop/tablet 使用两列；统一列宽让标题、简介和日期更舒展。
- 两列之间使用留白，条目仍是普通列表单元，只保留底部分隔线，不使用圆角卡片、背景块或阴影。
- 文章列表和“全部收藏”混合时间流保持单列，保证摘要、作者和时间信息的阅读宽度。
- 网站标题点击外链；GitHub 行显示 `owner/repo` 与 stars 快照；文章行进入站内详情。
- 文章列表额外提供月份筛选，日期显示原文 published，缺失时显示 saveTime。

```

- 标题、元信息与正文属于同一条 680–720 px 主阅读流，并以视口为基准真正居中。
- 目录与“针对当前文章问 AI”上下排列在主阅读列左侧的同一条 sticky 功能栏，不参与主列宽度计算，也不得把正文挤向右侧；tablet/mobile 将 AI 放在标题后、正文前，目录仍使用折叠入口。
- 正文宽 680–720 px，中文正文 17–18 px，行高 1.85。
- 目录宽 180 px，sticky；只有存在至少两个二级标题时显示。
- 图片严格限制在正文列内，与正文等宽，不使用横向 breakout。
- 外链始终显示“阅读原文”，不让用户误以为本站是原始发布者。
- 笔记与正文以一条明显分隔线分开，Utterances 加载失败时显示 GitHub Issues 链接。

## 8. 全局搜索

```text
Desktop overlay                           Mobile full screen
┌──────────────────────────────────┐      ┌──────────────────────────────┐
│ 搜索网站、GitHub 和文章…    Esc  │      │ ← 搜索                       │
├──────────────────────────────────┤      │ [输入关键词…]                 │
│ 全部  网站  GitHub  文章         │      │ 全部  网站  GitHub  文章      │
│                                  │      ├──────────────────────────────┤
│ 文章                             │      │ 最近搜索                     │
│ 如何构建可靠的 Agent Skill      │      │ Agent Skill                  │
│                                  │      │                              │
│ GitHub                           │      │ 搜索结果…                    │
│ cloudflare/skills                │      │                              │
└──────────────────────────────────┘      └──────────────────────────────┘
```

- 桌面浮层宽 680 px，位于视口上方 12%；移动端占满视口。
- 输入 150 ms debounce；空输入显示最近收藏，不伪造“热门搜索”。
- 结果按类型分组但共用键盘选择序列；`↑/↓` 移动、`Enter` 打开、`Esc` 关闭。
- v1 数据可在构建时生成轻量搜索索引并在浏览器本地搜索，不引入服务端 API。

## 9. 状态设计

| 状态 | 表现 | 恢复动作 |
|---|---|---|
| Loading | 列表使用 3–5 条单色文本骨架，不显示 spinner 墙 | 数据到达后原位替换 |
| Empty | “这里还没有收藏”＋返回全部分类 | 返回全部 / 清除筛选 |
| No result | 显示关键词和当前筛选范围 | 清除关键词或筛选 |
| Data error | 保留页面框架，正文区显示数据文件名称 | 重新加载页面 |
| Article missing | 显示元信息与原文链接，说明本地正文缺失 | 阅读原文 |
| Image missing | 保留 alt 文本和原始远程链接 | 打开原图 |
| Notes error | 正文不受影响，显示 GitHub Issues 降级入口 | 前往 GitHub |

## 11. 交互与无障碍

| 输入 | 范围 | 行为 |
|---|---|---|
| `⌘/Ctrl + K` | 全站 | 打开全局搜索 |
| `/` | 非输入状态 | 聚焦当前列表搜索 |
| `Esc` | 搜索、drawer、sheet | 关闭并恢复触发点 focus |
| `Enter` | 聚焦列表行 | 打开站内详情或外链 |
| `Tab` | 全站 | 按视觉顺序遍历可交互元素 |

- 所有文本与背景达到 WCAG AA 对比度。
- focus ring 使用 2 px accent，不仅依靠颜色变化表示选中。
- 支持 `prefers-reduced-motion`，关闭位移，仅保留瞬时透明度变化。
- 图片必须有可读 alt；装饰图标使用 `aria-hidden`。

## 13. 设计稿验收重点

第一轮只确认以下问题，不进入前端实现：

1. 温暖编辑式视觉是否适合长期个人知识库。
2. 首页采用“介绍＋最近收录”而非分类卡片墙是否符合预期。
3. 移动端是否接受固定底部四项导航。
4. 文章详情是否需要目录，以及 GitHub Issues 笔记放在正文末尾是否合适。
5. 博客是否继续隐藏，等原创内容出现后再开放。
